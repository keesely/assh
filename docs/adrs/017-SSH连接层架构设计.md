# ADR-017: SSH 连接层架构设计

## Status
accepted

## Date
2026-05-09

## Context

Phase 3 需要实现 SSH 连接层（asshc/infra/ssh/ + asshc/port/connector.go + asshc/service/connect.go），涉及以下架构决策：

1. **接口粒度**：连接管理（Dial/Close）与会话管理（Shell/Run）职责不同，应该分离还是合一？
2. **HostKey 验证**：v1 使用 `InsecureIgnoreHostKey()` 完全跳过检查，v2 是否需要 known_hosts 检查？
3. **Keepalive 心跳**：是否需要支持，如何配置？
4. **SSH Agent 支持**：v1 支持 `SSH_AUTH_SOCK`，v2 是否保留？

## Options Considered

### 接口粒度
- **统一接口**：一个 `SSHConnector` 包含所有方法（Connect/Close/Shell/Run）
- **分离接口**：`SSHConnector`（连接）+ `SSHSession`（会话）

### HostKey 验证（三个方案）
- **A) InsecureIgnoreHostKey**：完全跳过（v1 方式，简单但不安全）
- **B) known_hosts 强制检查**：安全但首次使用时需配置
- **C) 可配置策略 + hook**：默认 known_hosts，支持跳过，预留扩展接口

### Keepalive
- **A) 不实现**
- **B) 固定 60s**
- **C) 从配置读取**

## Decision

### 1. 接口分离：SSHConnector + SSHSession

```go
// port/connector.go
type SSHConnector interface {
    Connect(server *domain.Server) (*ssh.Client, error)
    Close(client *ssh.Client) error
}

// port/session.go
type SSHSession interface {
    Shell(client *ssh.Client) error
    Run(client *ssh.Client, cmd string) error
    RunWithOutput(client *ssh.Client, cmd string) (string, error)
}
```

理由：连接与会话是不同生命周期的职责——一个连接可以多次创建会话。分离后可以独立 mock、独立测试。

### 2. HostKey 可配置策略

认证顺序（认证方法链）：
1. 优先尝试 `SSH_AUTH_SOCK` Agent 签名器
2. 然后尝试私钥文件（KeyFile）
3. 最后尝试密码认证

### 3. Keepalive 从配置读取

从 `Server.Options["keepalive"]` 读取心跳间隔（秒），0 或不存在时不启用。

### 4. SSH Agent 保留

通过 `SSH_AUTH_SOCK` 环境变量支持 SSH Agent 认证，保留 v1 用户习惯。

### 5. Session 层继承 v1 能力

- pty 分配（xterm-256color）
- SIGWINCH 窗口大小变化处理
- stdout/stderr 接管

## Consequences

### 正面
1. 接口职责清晰，方便独立测试和 mock
2. HostKey 策略灵活，默认安全可降级
3. Keepalive 可配置，适应不同网络环境
4. SSH Agent 支持保留 v1 用户习惯
5. Service 层封装完整，CLI 层无需直接依赖 ssh 库

### 负面
1. 接口增加间接层，代码量略增
2. HostKey hook 接口在 Phase 3 仅预留定义，具体实现需后续 Phase 完善
