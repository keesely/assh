# ADR-012: CLI 参数对齐与命令架构

| 属性 | 值 |
|------|-----|
| ADR | #12 |
| Status | accepted |
| Date | 2026-05-09 |

## Context

Phase 4 实现 CLI 命令组装（cmd/），需要统一规范所有命令的参数命名和层级结构。

关键决策点：

1. **参数命名**：是否与 Linux ssh 参数对齐？如何平衡兼容性与 assh 特有需求？
2. **命令层级**：server 管理作为子命令还是顶级命令？login/run/bc 如何组织？
3. **login 自动识别**：参数自动判别直连或按名查找的策略和边界条件
4. **bc 输出架构**：批量执行命令的输出格式——实时日志、stdout 标头、JSON 汇总三通道
5. **全局参数与子命令参数**：哪些参数放在 app 级别，哪些放在子命令级别

## Options Considered

### 参数命名

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| A) 完全自创 | 所有参数按 assh 风格命名 | 自由度高 | 用户需重新学习 |
| B) 完全对齐 ssh | 所有参数与 ssh 一致 | 用户零学习成本 | assh 特有功能无对应参数 |
| **C) 兼容对齐** | **主力参数对齐 ssh，assh 特有参数使用合理命名** | **兼顾两者** | **部分参数无 ssh 对应** |

### 命令层级

| 方案 | 结构 | 说明 |
|------|------|------|
| A) 子命令模式 | `server add/ls/info/rm/mv` | server 作为子命令，管理功能归类 |
| B) 顶级命令模式 | `add, ls, info, rm, mv` | 所有命令扁平化 |
| **C) 混合模式** | **server 子命令 + login/run/bc 顶级命令** | **管理归类，常用简洁** |

## Decision

### 1. 参数对齐策略

采用 **方案 C: 兼容对齐**，参数与 Linux ssh 对齐，assh 特有功能使用合理命名：

| 参数 | assh | ssh 对应 | 语义 |
|------|------|----------|------|
| 端口 | `-p/--port` | `-p` | 远程端口 |
| 用户 | `-u/-l/--user/--login` | `-l` | 用户名 |
| 密钥 | `-i/--identity-file` 别名 `-k/--key` | `-i` | 身份文件 |
| 密码 | `-P/--password` | assh 特有 | 明文密码 |
| 选项 | `-o/--option` | `-o` | 配置项 |
| 详细 | `-v/--verbose` | `-v` | 详细输出 |
| 静默 | `-q/--quiet` | `-q` | 静默模式 |
| 主机 | `-H/--host` | assh 特有 | 目标主机 |
| 超时 | `-c/--connect-timeout` | `-o ConnectTimeout` | 连接超时 |
| 配置 | `-F/--config` | `-F` | 配置文件路径 |

### 2. 命令层次

采用 **方案 C: 混合模式**：

```
assh
├── server add     # 添加服务器
├── server ls      # 列出服务器
├── server info    # 查看服务器详情
├── server rm      # 删除服务器
├── server mv      # 重命名/移动服务器
├── login          # SSH 登录（按名/直连）
├── run            # 远程执行命令
├── bc             # 批量执行命令
└── version        # 版本信息
```

### 3. login 自动识别规则

```
参数输入 → 自动识别策略
   ├── 包含 "@" → 解析为 user@host 直连
   │               示例: assh root@10.0.0.1 -p 2222
   ├── 包含 "-H/--host" → 分离参数直连
   │               示例: assh -H 10.0.0.1 -u root -p 2222
   └── 纯名称 → 从数据库按名查找
                   示例: assh prod.web-01
```

### 4. bc 输出三通道架构

批量执行命令采用三层输出架构：

```
执行 bc "uptime" --servers prod.web-01,prod.web-02
   │
   ├── 通道1: 实时日志文件
   │   └── /tmp/assh/bclogs/{server_name}.log
   │       每台服务器独立日志文件，记录完整输出
   │
   ├── 通道2: stdout 实时输出
   │   └── [prod.web-01] 10:30:45 up 30 days...
   │       带服务器标头前缀，实时显示
   │
   └── 通道3: JSON 汇总（执行完毕后）
       ├── 工作目录: ./bc-result-{timestamp}.json（默认）
       └── --log /path/output.json（自定义）
           JSON 结构包含所有服务器执行结果
```

### 5. 参数作用域划分

| 作用域 | 参数 | 说明 |
|--------|------|------|
| **全局 (app)** | `-v/--verbose`, `-q/--quiet`, `-F/--config` | 所有命令共享 |
| **server 子命令** | `-P/--password`, `-k/--key`, `-i/--identity-file`, `-o/--option` | server add 特有 |
| **login/run** | `-p/--port`, `-u/--user/-l/--login`, `-P/--password`, `-i/--identity-file`, `-k/--key`, `-H/--host`, `-c/--connect-timeout`, `-o/--option` | 连接相关 |
| **bc 特有** | `--servers`, `--group`, `--log`, `-p/--port`（覆盖默认） | 批量执行 |

## Consequences

### Positive

- **学习成本低**：ssh 用户无需额外学习即可上手 assh
- **参数命名明确**：无歧义，长短参数完整（短参数用于终端快速操作，长参数用于脚本）
- **自动识别灵活**：支持多种输入方式，适应不同使用习惯
- **bc 日志完善**：实时反馈 + 持久化日志 + 结构化汇总，适合运维场景

### Negative

- **-H/--host 特有参数**：ssh 无此参数，但在 assh 中用于分离式直连，语义清晰可接受
- **-P/--password 明文风险**：明文密码参数可能被 bash history 记录，需在文档中提示用户避免使用，或提供交互式提示作为替代
- **参数数量增加**：较复杂的帮助信息，需配合 `--help` 说明

### Affected Modules

- `cmd/app.go` — 全局参数注册、命令注册入口
- `cmd/server.go` — 新建文件，server 子命令
- `cmd/connect.go` — 新建文件，login/run/bc 命令
- `main.go` — DI 注入调整
