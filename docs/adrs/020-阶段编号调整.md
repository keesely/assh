# ADR-020: 阶段编号调整 — 插入 Phase 6 密钥管理

## Status

accepted

## Date

2026-05-10

## Context

Phase 5（SFTP 文件传输）完成后，需要在 Phase 5 和 Phase 7 之间插入密钥管理（Key Management）功能。原有阶段编号从 Phase 5 直接跳到 Phase 7（代理 & 隧道），缺少密钥管理阶段。

密钥管理的需求来源：
- 用户直连（`assh root@host -P pass`）时需要自动记录 known_servers
- RQ-001 组合参数实现后，`-i`/`-k` 密钥参数与自动密钥管理需要联动
- 现有 `asshc/infra/crypto/` 已有 RSA/Ed25519/ECDSA 密钥生成能力，但缺少密钥存储和生命周期管理
- ADR-018（known-servers 隐性表）已有设计，需要在 Phase 6 落地

## Decision

插入 Phase 6（密钥管理），后续阶段编号顺移：

| 原编号 | 新编号 | 阶段 |
|--------|--------|------|
| Phase 5 | Phase 5 | SFTP 文件传输（当前） |
| — | **Phase 6** | **密钥管理 (Key Management)** ← 新增 |
| Phase 6 | Phase 7 | 代理 & 隧道 |
| Phase 7 | Phase 8 | 云同步 (Qiniu) |
| Phase 8 | Phase 9 | 服务器健康检查 |
| Phase 9 | Phase 10 | 跳板机支持 |
| Phase 10 | Phase 11 | 远程服务器挂载 |
| Phase 11 | Phase 12 | 自动更新/升级 |

Phase 6 职责范围：
- K.1 KeyManager 接口（`port/keymgr.go`）
- K.2 RSA/Ed25519 密钥对生成（复用 `infra/crypto/`）
- K.3 加密存储与密钥文件管理
- K.4 KeyService 编排
- K.5 known-servers 表落地（ADR-018）
- K.6 SSH 客户端自动注入已存密钥
- K.7 `-K`/`--keygen` 命令

依赖关系：
- Phase 3 (SSH) → Phase 6 (Key Management) → Phase 4 (CLI)
- Phase 6 不依赖 Phase 5 (SFTP) — 可并行开发
- Phase 6 不依赖 Phase 7+ — 无需等待

## Consequences

正面：密钥管理功能获得独立阶段，职责清晰；与 known-servers（ADR-018）自然衔接；可并行于 Phase 5 开发。

负面：所有 ADR 中引用的 "Phase X" 编号需要全局更新；用户文档中的阶段规划需要同步。

影响：ADR-017 中 "Phase 10 挂载功能" 需更新为 "Phase 11"；所有 docs 文件中的阶段引用需执行全量 `rg 'Phase [0-9]+' --type md` 扫描。
