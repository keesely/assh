# ADR-022: Phase 5 SFTP 验收标准拆分 (F1-F28)

## Status

accepted

## Date

2026-05-10

## Context

Phase 5（SFTP 文件传输）包含多个功能维度：基础传输（push/pull）、断点续传、覆盖策略、Glob 匹配、校验和验证、交互式会话、CLI 组合参数等。需要将 Phase 5 的功能拆分为可验证的验收标准，确保每个功能点可独立测试和验收。

## Decision

采用 F1-F28 编号体系，按功能域分组：

| 域 | 编号范围 | 功能 |
|----|----------|------|
| 基础传输 | F1-F4 | push/pull 单文件、递归目录 |
| 覆盖策略 | F5-F8 | 断点续传、强制覆盖、跳过、询问 |
| 边缘/安全 | F14-F20 | Glob 平铺、Server 不存在、SHA256 校验、验证失败、批量续传、断点边界 |
| 交互式 | F21 | sftp 交互会话完整命令集 |
| CLI 增强 | F22-F28 | RQ-001 组合短参数 7 项验收 |

单文件 `docs/TODO.md` 内维护完整验收清单，每项包含：编号、场景描述、操作命令、预期结果、状态标记（✅/❌）。

状态标记约定：
- ✅ = 已实现且测试通过
- ⚠️ = 已实现但未测试（高风险）
- ❌ = 未实现

## Consequences

正面：验收标准结构化，便于跟踪进度；每个 F 项可独立测试；验收标准与 TODO 任务在同一文件中维护，减少信息分散。

负面：F1-F28 编号不连续（F9-F13 为 Phase 4 保留），可能导致混淆；验收标准与任务清单在同一文件，文件较长。

影响范围：
- `docs/TODO.md` Phase 5 验收清单表格（F1-F28）
- AGENTS.md 中的 Phase 5 状态描述
- 各 F 项的测试命令和预期行为
