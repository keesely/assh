# ADR-016: 顶层默认登录行为（v1 兼容）

## Status
accepted

## Date
2026-05-10

## Context
v2 当前需要显式输入 `assh login <target>` 才能登录，而 v1 支持直接在顶层输入 `assh <target>` 自动触发登录（如 `assh root@localhost`、`assh test-box`、`assh dev.test-server`）。用户反馈 v2 的 login 命令增加了不必要的输入步骤，不利于快速登录。

v1 使用 urfave/cli 的默认 Action 实现此行为：当第一个参数不匹配任何已知命令名时，匹配失败后自动走默认 Action 的登录逻辑，从而实现无缝直连。

## Decision
在 `app.go` 中设置 `app.Action = a.defaultAction`，使其行为与 v1 一致：

1. `assh <name>` — 按服务器名查数据库登录
2. `assh user@host` — 直连登录
3. `assh dev.test-server` — 带分组服务器名查数据库登录
4. `assh <target> -c <cmd>` — 登录后执行远程命令
5. 添加全局参数 `-c/--command` 支持 v1 的命令执行方式
6. 如果第一个参数匹配已知命令名（add/set/ls/login/run 等），正常执行对应命令，不受默认 Action 影响
7. `login` 命令保留，作为显式登录的备选

### 实现方式
将 `loginAction` 中的连接核心逻辑提取为 `loginCore(c *cli.Context) (*ssh.Client, error)` 方法，供给 `loginAction` 和 `defaultAction` 共同调用。`defaultAction` 在获取连接后检查 `-c` 参数：有则执行命令（Run），无则进入交互式 Shell。

## Consequences

### 正面
- 与 v1 行为完全兼容，用户无需改变使用习惯
- 减少击键次数，提升日常效率

### 负面
- 默认 Action 的触发条件依赖于 urfave/cli 的命令匹配机制，如果未来新增的命令名与用户自定义的服务器名相同，可能产生歧义（可通过 `login` 命令绕过）
