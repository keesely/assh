# ADR-026: SSH 连接密钥备份优先策略

## Status

accepted

## Date

2026-05-13

## Context

Phase 6 密钥管理实现中，需要解决以下问题：

1. **密钥备份优先策略（P6.6-a）**：当用户配置了 `-k ~/.ssh/id_rsa` 时，密钥文件可能因误操作被篡改或删除。需要实现备份优先策略，确保登录时优先使用 `data/keys/` 中的备份密钥。

2. **passphrase 管理**：备份密钥使用 account password 加密存储，SSH 连接时需要解密。需要确定如何将 passphrase 传递给 SSH Connector。

3. **known-servers 密钥查找（P6.6-b）**：直连登录（user@host / -H host）后，如果之前执行过 `assh keygen -H ...`，直连第二次应该自动使用 known_servers 中记录的 `key_backup_path` 连接。

### 问题背景

当前 `sshinfra/client.go` 的 `tryKeyFile` 方法实现如下：

```go
func (c *Connector) tryKeyFile(keyFile string) ssh.AuthMethod {
    key, err := os.ReadFile(keyFile)
    if err != nil {
        return nil
    }
    signer, err := ssh.ParsePrivateKey(key)
    if err != nil {
        return nil
    }
    return ssh.PublicKeys(signer)
}
```

存在的问题：
- 直接读取 `Auth.KeyFile` 路径，无备份查找逻辑
- 无法处理加密的备份密钥（需要 passphrase）
- 直连时无法利用 known_servers 中的 `key_backup_path`

### 可选方案

#### 方案 A：Connector 持有 accountPassphrase（推荐）

```go
// Connector 持有 passphrase
type Connector struct {
    accountPassphrase []byte
}

func NewConnectorWithPassphrase(passphrase []byte) *Connector {
    return &Connector{accountPassphrase: passphrase}
}

// tryKeyFile 实现备份优先
func (c *Connector) tryKeyFile(keyFile string) ssh.AuthMethod {
    // 1. 优先查找 data/keys/ 备份
    if c.accountPassphrase != nil {
        if m := c.tryBackupKey(keyFile); m != nil {
            return m
        }
    }
    // 2. 回退到原始路径
    ...
}

// tryBackupKey 从 data/keys/{hash}/key.pem 加载并解密
func (c *Connector) tryBackupKey(keyFile string) ssh.AuthMethod {
    backupPath := computeKeyBackupPath(keyFile)
    key, err := os.ReadFile(backupPath)
    if err != nil {
        return nil
    }
    // 优先用 passphrase 解密，失败则尝试无 passphrase 解析
    signer, err := ssh.ParsePrivateKeyWithPassphrase(key, c.accountPassphrase)
    if err != nil {
        signer, err = ssh.ParsePrivateKey(key)
        if err != nil {
            return nil
        }
    }
    return ssh.PublicKeys(signer)
}
```

**优点**：
- 实现简单，passphrase 通过构造函数注入
- 备份密钥自动解密
- 兼容未加密的密钥（fallback 到无 passphrase 解析）

**缺点**：
- Connector 需要知道 passphrase（但 passphrase 来自 KeyManager，耦合可接受）

#### 方案 B：解密器接口

```go
type KeyDecryptor interface {
    DecryptKey(key []byte) (*ssh.Signer, error)
}

func NewConnector(decryptor KeyDecryptor) *Connector
```

**优点**：
- 完全解耦

**缺点**：
- 过度工程化（只需要解密一个 []byte → *ssh.Signer）
- 实现复杂

#### 方案 C：不加密备份密钥

**优点**：
- Connector 无需 passphrase

**缺点**：
- 安全风险：备份密钥明文存储
- 与 Phase 6 设计冲突（密钥应使用 account password 加密）

#### 方案 D：连接前预处理

在 main.go 中，连接前将备份密钥解密并传给 Connector。

**优点**：
- Connector 无需 passphrase

**缺点**：
- 每次连接前都需要额外处理
- 实现复杂

## Decision

采用 **方案 A：Connector 持有 accountPassphrase**。

### 实现细节

1. **Connector 构造函数**：
   - `NewConnector()` — 无 passphrase，向后兼容
   - `NewConnectorWithPassphrase(passphrase []byte)` — 持有 passphrase

2. **tryKeyFile 逻辑**：
   ```
   if passphrase != nil:
       tryBackupKey(keyFile) → 成功则使用备份
   fallback: ReadFile(keyFile) → 原始路径
   ```

3. **tryBackupKey 逻辑**：
   ```
   backupPath = data/keys/{sha256(keyFile)}/key.pem
   ReadFile(backupPath) → 存在则解密/解析
   ParsePrivateKeyWithPassphrase(key, passphrase) → 优先加密
   ParsePrivateKey(key) → fallback 未加密密钥
   ```

4. **ConnectDirect 新增 keyBackupPath 参数**：
   ```go
   func (s *ConnectService) ConnectDirect(host string, port int, user, password, keyFile string, keyBackupPath string) (*ssh.Client, error)
   ```
   用于直连 keygen 后复用 known_servers 中的密钥路径。

5. **main.go 注入顺序调整**：
   ```
   1. 创建 KeyManager（获取 passphrase）
   2. 创建 ConnectorWithPassphrase
   3. 创建 ConnectService（注入带 passphrase 的 Connector）
   ```

### 备份目录结构

```
~/.assh/v2/data/keys/
├── {ab}/
│   └── {cd}/
│       └── {hash[4:]}.pem              # keygen 生成的密钥（按内容 SHA256，前4字符为目录）
├── {ab}/
│   └── {cd}/
│       └── {hash[4:]}.pem              # BackupKey 快照（按原始路径 SHA256，前4字符为目录）
└── ...
```

说明：
- `{ab}` 为 SHA256 哈希的前 2 个字符
- `{cd}` 为 SHA256 哈希的第 3-4 个字符
- `{hash[4:]}` 为 SHA256 哈希的第 5 个字符到末尾（不含扩展名）
- 示例：`keys/ab/cd/efghijklmnop.pem`

## Consequences

### 正面

- 密钥备份优先策略实现完成，原始密钥被篡改/删除时自动使用备份
- 加密密钥自动解密，无需手动处理 passphrase
- 直连 keygen 后自动复用 known_servers 中的密钥路径

### 负面

- Connector 与 KeyManager 产生依赖关系（通过 passphrase）
- 备份密钥目录结构：`data/keys/{ab}/{cd}/{hash[4:]}.pem`（三层嵌套）

### 影响范围

| 文件 | 变更 |
|------|------|
| `asshc/infra/ssh/client.go` | Connector 新增 `accountPassphrase` 字段 + `tryBackupKey` + `computeKeyBackupPath` |
| `asshc/service/connect.go` | `ConnectDirect` 新增 `keyBackupPath` 参数 |
| `main.go` | 调整创建顺序：KeyManager → ConnectorWithPassphrase → ConnectService |
| `asshc/service/connect_test.go` | 测试签名更新（5 处） |
| `cmd/connect.go` | 调用处更新（2 处） |
