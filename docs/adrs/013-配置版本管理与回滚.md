# ADR-013: 配置版本管理与回滚机制

| 属性 | 值 |
|------|-----|
| ADR | #013 |
| Status | accepted |
| Date | 2026-05-09 |

## Context

Phase4 新增 `server set` (upsert) 和 `server rollback` 命令，需要持久化记录服务器配置的每次变更。设计上需要决定：

1. **快照存储策略**：完整快照 vs 增量变更
2. **密码处理方式**：快照中密码明文 vs 加密
3. **回滚语义**：覆盖历史 vs 追加新版本
4. **事务保证**：原子性策略
5. **版本管理**：自动 vs 手动

## Decision

### 1. 完整快照（JSON）

每次 `Set` 操作将完整的 `domain.Server` 序列化为 JSON，存入 `server_changelog.snapshot` 列。完整快照的优点是回滚时可以独立恢复任意版本，无需依赖其他版本的增量数据。

### 2. 密码明文存储

快照中包含密码明文，与 `servers` 表的密码列同级安全约束（均在同一 SQLite 文件中）。后续可通过快照加密增强。

### 3. 回滚追加新版本

回滚不覆盖历史记录，而是创建新的版本条目（`change_type=rollback`），保证可审计性：
- 版本号持续递增（取当前最大版本 +1）
- 回滚后的配置与目标版本一致
- 可再次回滚到之前的任意版本

### 4. SQLite 事务

`Set` 和 `RollbackTo` 均使用 SQLite 事务包裹：
```
BEGIN;
  INSERT OR REPLACE INTO servers ...;
  INSERT INTO server_changelog ...;
COMMIT;
```

保证数据更新和日志记录原子一致性。

### 5. 版本自动管理

版本在 `store.Set()` 中自动管理，`service/` 和 `cmd/` 层无感知：
- 新建服务器：version = 1
- 更新已有：version = current + 1
- 回滚：version = max(all versions) + 1

## Consequences

### 正面
- 完整审计跟踪：每次变更都可追溯
- 一键回滚：无需手动备份和恢复
- 版本自动管理：开发层无感知

### 负面
- 快照含明文密码（与 `servers` 表同风险级别）
- 存储空间随变更次数线性增长（每条 JSON 快照记录）
- 无法回滚清除的服务器（删除不保留 changelog）

### 影响范围

| 模块 | 变更 |
|------|------|
| `store.Set()` | 数据库写入 + 快照记录（事务包裹） |
| `store.RollbackTo()` | 新增方法：快照反序列化 → 恢复 |
| `store.GetChangelog()` | 新增方法：查询变更历史 |
| `service.SetServer()` | 新增 upsert 方法 |
| `service.RollbackServer()` | 新增回滚方法 |
| `service.GetServerChangelog()` | 新增查询方法 |
| `cmd/server.go` | set 命令（重命名+upsert） + rollback 命令 |
