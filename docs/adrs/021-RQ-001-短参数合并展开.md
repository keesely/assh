# ADR-021: RQ-001 — CLI 组合短参数支持（-qnt 风格）

## Status

accepted

## Date

2026-05-10

## Context

assh CLI 应支持像 SSH 那样使用组合短参数，例如 `assh root@host -qnt` 等价于 `assh root@host -q -n -t`。

动机：
- SSH、git、tar 等标准 Unix 工具均支持组合短参数
- 减少击键次数
- 与 v1 版本的 CLI 体验保持一致

当前 assh 基于 urfave/cli v1.22.2，该框架不原生支持组合短参数。

当前短参数占用情况：-v(verbose)、-q(quiet)、-V(version)、-F(config)、-c(command)、-p(port)、-u(user)、-l(login)、-P(password)、-i(identity)、-k(key)、-H(host)。几乎所有 a-z、A-Z 已被占用，最终只剩 -e(resume) 可用。

## Decision

在 `main.go` 中 `app.Run(os.Args)` 之前对 `os.Args` 做预处理，实现 `expandCombinedFlags()` 函数：

1. 定义已知 bool flag 白名单：`{"v": true, "q": true, "V": true}`
2. 预处理逻辑：以 `-` 开头且长度 > 2 的参数，逐字符检查是否全为已知 bool flag：
   - 全为 bool flag → 展开为独立参数
   - 含有非 bool flag → 保持原样交给 urfave/cli 处理（会自然报错）
3. 边界处理：
   - `-p22` 保持原样（形如 `-<flag><value>` 风格）
   - `--` 分隔符后不处理
   - 混入未知 flag 时 urfave/cli 会报错
   - 长参数（`--quiet`）不受影响

## Consequences

正面：零框架侵入，纯预处理实现；与 urfave/cli 的现有行为完全兼容；带值短参（-p、-u、-i 等）不受影响。

负面：bool flag 白名单需要手动维护，新增 bool 短参时必须同步更新。

验收标准（F22-F28）：
- F22: `-qv` → `-q -v`
- F23: `-qVv` → `-q -V -v`
- F24: `-q` 单参数不变
- F25: `-qv root@host -c "uptime"` 混用正常
- F26: `--quiet --verbose` 长参数不受影响
- F27: `-qx` 含未知 flag 报错
- F28: `-qp` 混入带值短参不展开
