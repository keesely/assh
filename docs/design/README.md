## 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                      用户界面层 (CLI)                        │
│                          cmd/                                │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      应用服务层 (Service)                    │
│                     service/ + port/                         │
│              （用例编排 + 接口定义）                          │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        领域层 (Domain)                       │
│                        domain/                              │
│              （实体 + 值对象 + 领域错误）                    │
└─────────────────────────────────────────────────────────────┘
                              ▲
                              │
┌─────────────────────────────┴───────────────────────────────┐
│                    基础设施层 (Infrastructure)                │
│                         infra/                              │
│           （SQLite + SSH + SFTP + 代理 + 同步）              │
└─────────────────────────────────────────────────────────────┘
```

## 核心原则

1. **依赖倒置**: 服务层依赖端口接口，不依赖基础设施实现
2. **接口隔离**: 端口接口小而专注
3. **领域为核心**: 所有业务逻辑围绕领域模型展开
4. **六边形架构**: 通过端口和适配器隔离外部依赖
