# NEXT-001: Proxy & Tunnel 增强设计文档

> 日期: 2026-05-29
> 分支: dev/v2.1.0-phase-12
> 状态: 设计中

## 1. 背景与目标

### 1.1 现状问题

Phase 7 完成的代理/隧道基础功能存在以下问题：

| 问题 | 现状 | 影响 |
|------|------|------|
| `--http` 参数无效 | `assh proxy --http :8080` 仅启动 SOCKS5，HTTP CONNECT 未生效 | 用户困惑 |
| `--tcp`/`--http-mode` 语义不清 | 仅用于反向模式，正向固定 SOCKS5 | 参数不一致 |
| tunnel 命令冗余 | 需要 `assh tunnel start myserver -L 8080:localhost:80` | 不够简洁 |
| 缺少传输层类型指定 | 端口转发仅支持 TCP | 无法支持 HTTP 代理 |
| 端口参数不支持自动补全 | `8080::80` 中间为空 host 时报错 | 用户体验差 |
| 无服务持久化 | 服务启动后无数据库记录 | 重连/重启后无法恢复 |

### 1.2 设计目标

1. **统一参数体系**：`--http`/`--tcp`/`--socks` 按目标端决定服务类型
2. **简化 tunnel 命令**：去除 `start` 子命令，直接 `assh tunnel server -L/-R`
3. **支持 --listen http**：在远程服务器启动 HTTP Server（参考 v1 hostproxy/localproxy）
4. **端口参数自动补全**：空 host 自动补全为 `127.0.0.1`
5. **SQLite 服务管理**：持久化服务记录，支持自动重连恢复

## 2. 设计方案

### 2.1 参数体系重构

#### proxy 命令变更

**现有参数**:
```
--socks5 :1080      # SOCKS5 代理（本地监听）
--http :8080        # HTTP CONNECT 代理（本地监听）— 当前无效
--reverse           # 反向代理模式
--tcp               # 反向 TCP 模式（仅用于反向）
--http-mode         # 反向 HTTP 模式（仅用于反向）
--ports 80:3000     # 端口映射规则（反向模式）
```

**新参数体系**:
```
--socks :1080       # 启用 SOCKS 代理（本地监听）
--http :8080        # 目标端启动 HTTP Server（远程监听）
--tcp :9090         # 目标端启动 TCP Server（远程监听）
--reverse           # 反向模式：目标端为本地
--ports 80:3000     # 端口映射规则
--listen tcp|http   # 传输层类型（默认 tcp）
```

**使用示例**:
```bash
# 正向代理（本地监听）
assh proxy myserver --socks :1080           # SOCKS5 代理
assh proxy myserver --socks :1080 --http :8080  # SOCKS5 + HTTP

# 远程监听（目标端为远程服务器）
assh proxy myserver --http :8080            # 在 myserver 启动 HTTP Server :8080
assh proxy myserver --tcp :9090             # 在 myserver 启动 TCP Server :9090

# 反向代理（目标端为本地）
assh proxy myserver --reverse --http :8080  # 本地启动 HTTP Server :8080
assh proxy myserver --reverse --tcp --ports 80:3000  # 本地 TCP 端口映射
```

#### --listen http 实现方案

**v1 hostproxy/localproxy 分析**:

v1 中的 `localproxy` 功能描述：
- 在远程服务器上启动 HTTP Server
- 监听指定端口
- 将 HTTP 请求转发到指定目标

**v2 实现方案**:

```go
// 1. SSH 连接到目标服务器
client, err := connector.Connect(server)

// 2. 通过 SSH channel 建立隧道
// 方案 A: 使用 ssh.Client.ListenRemote (需要服务器 AllowTcpForwarding)
listener, err := client.Listen("tcp", ":8080")

// 方案 B: 通过 SSH exec 在远程启动 HTTP 代理进程
session, err := client.NewSession()
session.Start("assh-proxy-server --listen :8080 --forward-to localhost:3000")

// 3. 接受连接并转发
for {
    conn, err := listener.Accept()
    go handleHTTPProxy(conn, targetAddr)
}
```

**推荐方案**: 方案 A（SSH Remote Forward），更简洁可靠

**实现细节**:
1. 使用 `ssh.Client.Listen()` 在远程监听端口
2. 接受连接后，建立到目标的连接
3. 双向转发数据（支持 HTTP 协议解析）

### 2.2 tunnel 命令简化

**现有命令**:
```bash
assh tunnel start myserver -L 8080:localhost:80
assh tunnel stop <id>
assh tunnel list
```

**新命令**:
```bash
assh tunnel myserver -L 8080:localhost:80      # 直接启动（去除 start）
assh tunnel myserver -R 8080:localhost:80      # 远程转发
assh tunnel stop <id>                          # 保留 stop
assh tunnel list                               # 保留 list
```

**实现方案**:

修改 `cmd/tunnel.go`：
```go
func (a *App) registerTunnelCommands() {
    a.cli.Commands = append(a.cli.Commands, cli.Command{
        Name:      "tunnel",
        Usage:     "Manage SSH port forwarding tunnels",
        ArgsUsage: "<server> [-L/-R spec]",
        Flags: []cli.Flag{
            cli.StringSliceFlag{Name: "L", Usage: "local forward spec"},
            cli.StringSliceFlag{Name: "R", Usage: "remote forward spec"},
            cli.StringFlag{Name: "listen", Value: "tcp", Usage: "listen type: tcp|http"},
            // ... 其他 flags
        },
        Action: a.tunnelAction,  // 直接处理，无需 start 子命令
        Subcommands: []cli.Command{
            {Name: "stop", ...},
            {Name: "list", ...},
        },
    })
}
```

### 2.3 端口参数自动补全

**现有问题**:
```bash
assh tunnel myserver -L 8080::80  # 解析失败，host 为空
```

**目标行为**:
```bash
assh tunnel myserver -L 8080::80  # 等价于 8080:127.0.0.1:80
assh tunnel myserver -L 80::80    # 等价于 80:127.0.0.1:80
```

**实现方案**:

修改 `parseForwardSpec` 函数：
```go
func parseForwardSpec(spec string) (localAddr, remoteAddr string) {
    parts := strings.Split(spec, ":")

    switch len(parts) {
    case 3:
        // port:host:hostport
        host := parts[1]
        if host == "" {
            host = "127.0.0.1"  // 自动补全
        }
        return fmt.Sprintf("127.0.0.1:%s", parts[0]), fmt.Sprintf("%s:%s", host, parts[2])
    case 4:
        // bind:port:host:hostport
        host := parts[2]
        if host == "" {
            host = "127.0.0.1"  // 自动补全
        }
        return fmt.Sprintf("%s:%s", parts[0], parts[1]), fmt.Sprintf("%s:%s", host, parts[3])
    default:
        return "", ""
    }
}
```

### 2.4 SQLite 服务管理

#### 2.4.1 领域实体

```go
// domain/service.go
type ServiceType string
const (
    ServiceTypeProxy  ServiceType = "proxy"
    ServiceTypeTunnel ServiceType = "tunnel"
)

type ServiceStatus string
const (
    ServiceStatusRunning ServiceStatus = "running"
    ServiceStatusStopped ServiceStatus = "stopped"
    ServiceStatusFailed  ServiceStatus = "failed"
)

type ServiceInstance struct {
    ID          string            `json:"id"`
    Name        string            `json:"name"`
    Type        ServiceType       `json:"type"`
    ServerName  string            `json:"server_name"`
    Status      ServiceStatus     `json:"status"`
    Config      ServiceConfig     `json:"config"`
    PID         int               `json:"pid,omitempty"`
    CreatedAt   time.Time         `json:"created_at"`
    UpdatedAt   time.Time         `json:"updated_at"`
}

type ServiceConfig struct {
    ListenType    string   `json:"listen_type,omitempty"`   // tcp/http
    LocalAddr     string   `json:"local_addr,omitempty"`
    RemoteAddr    string   `json:"remote_addr,omitempty"`
    Reverse       bool     `json:"reverse"`
    Auth          string   `json:"auth,omitempty"`
    Ports         string   `json:"ports,omitempty"`
    AutoReconnect string   `json:"auto_reconnect,omitempty"`
}
```

#### 2.4.4 数据库设计

```sql
CREATE TABLE IF NOT EXISTS services (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    name               TEXT NOT NULL UNIQUE,
    type               TEXT NOT NULL CHECK(type IN ('proxy','tunnel')),
    server_name        TEXT NOT NULL,
    status             TEXT NOT NULL DEFAULT 'stopped' CHECK(status IN ('running','stopped','failed')),
    config_encrypted   BLOB,              -- AES-GCM 加密的服务配置快照
    pid                INTEGER DEFAULT 0,
    created_at         TEXT DEFAULT (datetime('now')),
    updated_at         TEXT DEFAULT (datetime('now'))
);
```

## 4. 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SSH Remote Forward 需要服务器配置 | 高 | 检测 `AllowTcpForwarding`，提供配置指引 |
| 远程 HTTP Server 实现复杂度 | 高 | 先实现简单 HTTP 代理，支持基本转发 |
| 服务管理状态一致性 | 中 | 使用数据库事务，确保状态原子更新 |
| 向后兼容性 | 中 | 保留旧参数别名，提供迁移指引 |
