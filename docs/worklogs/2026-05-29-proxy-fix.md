# 2026-05-29 Proxy Flag 解析修复

## 问题描述

用户执行 `./assh proxy ali.24 --http :8009 --ports 8009:4096` 时，`--http` 和 `--ports` 参数未被解析，直接启动了 SOCKS5 代理。

## 诊断过程

1. 添加调试日志到 `proxyAction` 和 `startProxyWithClient`
2. 发现所有 flag 值为空：`HTTPAddr=\"\", Ports=\"\"`
3. args 显示所有参数被当作位置参数：`args=[ali.24 --http :8009 --ports 8009:4096], NArg=5`

## 根因

**urfave/cli v1 的 bug**：当 Command 有 Subcommands 时，flag 解析异常。

原代码中 proxy 命令包含 Subcommands（rule、log），导致 CLI 框架无法正确解析 flag。

## 解决方案

将 Subcommands 从 proxy 命令中移除，改为独立的顶级命令：

```go
// 原来
cli.Command{
    Name: "proxy",
    Subcommands: []cli.Command{
        {Name: "rule", ...},
        {Name: "log", ...},
    },
}

// 改为
cli.Command{Name: "proxy", ...}           // 无 Subcommands
cli.Command{Name: "proxy-rule", ...}      // 独立命令
cli.Command{Name: "proxy-log", ...}       // 独立命令
```

## 修复的文件

- `asshv2/cmd/proxy.go` — 重构命令注册，移除 Subcommands
- `asshv2/asshc/service/proxy.go` — 修复 `startRemoteListenMode` 端口映射逻辑

## 端口映射逻辑修复

原代码 bug：
```go
remoteAddr := fmt.Sprintf("0.0.0.0:%s", listenAddr)
localAddr = fmt.Sprintf("127.0.0.1:%s", listenAddr)  // 错误：覆盖了 localAddr
```

修复后：
```go
remoteAddr := fmt.Sprintf("0.0.0.0:%s", listenPort)
localAddr := fmt.Sprintf("127.0.0.1:%s", localPort)  // 正确：使用 --ports 指定的本地端口
```

## 验证

```bash
# 测试命令
./assh proxy ali.24 --http :8009 --ports 8009:4096

# 预期结果
# - 远程监听 0.0.0.0:8009
# - 转发到本地 127.0.0.1:4096
```

## 经验教训

1. urfave/cli v1 在 Command 有 Subcommands 时存在 flag 解析问题
2. 调试 CLI 参数问题时，添加日志输出 args 和 NArg 是有效手段
3. 端口映射逻辑需要仔细区分远程端口和本地端口
