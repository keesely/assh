## 关键设计决策

### 1. NEXT-001 --listen http 实现

**用户需求**: 参考 v1.0.4 的 hostproxy/localproxy 实现

**v1 设计分析**:
- `proxy` - SOCKS5 代理（本地监听）
- `hostproxy` - 远程端口转发到本地（类似 `ssh -L`）
- `localproxy` - 本地端口转发到远程（类似 `ssh -R`）

**v2 --listen http 设计**:
```
# 在远程服务器启动 HTTP Server，监听指定端口
assh tunnel myserver --listen http -R 8080:web:80

# 等价于：
# 1. SSH 连接到 myserver
# 2. 在 myserver 上启动 HTTP Server 监听 8080
# 3. HTTP Server 将请求转发到 web:80
```

**实现方案**:
- 通过 SSH exec 在远程服务器启动 HTTP 代理进程
- 使用 channel 隧道建立 HTTP 通信
- 支持 HTTP/HTTPS 协议

### 2. Phase 12 协议选择

**用户决策**: sshfs + webdav（优先）

**理由**:
- sshfs: 依赖系统命令，实现最简单
- webdav: Go 库支持成熟（如 github.com/studio-b12/webdav）
- samba: 留待后续版本

### 3. NEXT-001 参数体系重构

**目标**: 统一 proxy/tunnel 参数语义

| 变更 | 现状 | 目标 |
|------|------|------|
| `--http` | 无效 | 目标端启动 HTTP Server |
| `--tcp` | 仅反向 | 目标端启动 TCP 服务 |
| `--socks` | 固定 SOCKS5 | 启用 SOCKS 代理 |
| `--listen` | 无 | 枚举值 tcp/http |
| tunnel start | 需要 start 子命令 | 直接 `assh tunnel server -L/-R` |
