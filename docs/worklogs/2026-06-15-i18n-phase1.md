## 一、任务概述

搭建项目国际化基础设施，包括：
- 添加 go-i18n 依赖
- 创建 i18n 包（语言检测、翻译加载、模板变量）
- 创建中英文翻译文件
- 创建翻译模板

## 二、技术选型

| 项目 | 选择 | 理由 |
|------|------|------|
| i18n 库 | `github.com/nicksnyder/go-i18n/v2` | Go 生态最成熟，支持 YAML，复数规则丰富 |
| 文件格式 | YAML | 结构清晰，易读易维护，支持嵌套 |
| 键命名 | 点分层次 | 如 `cmd.server.add.success`，结构化，易维护 |
| 语言切换 | 环境变量 | 符合 POSIX 标准，用户友好 |
| 默认语言 | 中文 (zh-CN) | 项目主要用户语言 |

### 3.2 i18n 包设计

**文件**: `internal/i18n/i18n.go`

**核心接口**:
```go
// Init 初始化 i18n 系统
func Init(langDir string) error

// T 返回翻译后的文本
func T(key string, args ...interface{}) string

// TWithLang 使用指定语言返回翻译
func TWithLang(lang, key string, args ...interface{}) string

// GetCurrentLang 返回当前语言
func GetCurrentLang() string

// SetLang 设置语言
func SetLang(lang string)

// IsInitialized 返回是否已初始化
func IsInitialized() bool

// SupportedLanguagesList 返回支持的语言列表
func SupportedLanguagesList() []string
```

**语言检测优先级**:
1. `ASSH_LANG` 环境变量（专用）
2. `LC_ALL` 环境变量
3. `LANG` 环境变量
4. 默认：`zh-CN`

**语言代码规范化**:
- `en_US.UTF-8` → `en-US`
- `zh_CN` → `zh-CN`
- `en` → `en-US`
- `zh` → `zh-CN`

### 3.3 翻译文件结构

**目录**: `i18n/`
- `zh-CN.yaml` - 中文翻译
- `en-US.yaml` - 英文翻译
- `template.yaml` - 翻译模板（空值）

**键命名规范**:
```
# 通用消息
common.success
common.error

# 命令模块
cmd.server.add.success
cmd.server.add.error.name_required

# 服务层
service.transfer.push.success

# 基础设施层
infra.ssh.hostkey.unverified
```

**模板变量语法**:
```yaml
cmd.server.add.success: "服务器 {{.Name}} 已添加 (v{{.Version}})"
```

## 八、经验总结

### 8.1 技术要点

1. **go-i18n Bundle 机制**: Bundle 是翻译的容器，Localizer 是语言特定的翻译器
2. **模板变量**: 使用 `{{.Variable}}` 语法，支持 map[string]interface{} 参数
3. **语言检测**: 标准化处理 locale 字符串（去除编码后缀，转换分隔符）
4. **Fallback 机制**: 翻译缺失时返回键名，确保不会崩溃

### 8.2 注意事项

1. **翻译键一致性**: 中英文 YAML 文件的键必须完全一致
2. **模板变量**: 翻译文本中的变量名必须匹配
3. **编码问题**: YAML 文件使用 UTF-8 编码
4. **性能**: Bundle 初始化只需一次，Localizer 创建开销很小

### 8.3 可复用模式

1. **语言检测函数**: `normalizeLang()` 可复用于其他项目
2. **环境变量优先级**: ASSH_LANG > LC_ALL > LANG > Default
3. **翻译键命名**: 点分层次命名，按模块/功能/消息类型组织
