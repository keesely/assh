# BUG-010: SSH 密钥认证失败后未回退到密码认证

## Status

fixed

## Date

2026-05-11

## Description

当服务器同时配置了 password 和 key 时，key 认证失败后 password 未被尝试。
实际报错仅为 key 认证失败的错误，用户无法使用密码作为回退方式连接服务器。

复现条件：
- 服务器配置中同时存在 `Auth.KeyFile` 和 `Auth.Password`
- 密钥文件有效但被 SSH 服务器拒绝（如密钥未注册到 authorized_keys）
- 服务器支持密码认证

错误输出：
```
error: ssh dial failed: ssh: handshake failed: ssh: unable to authenticate, attempted methods [none publickey], no supported methods remain
```

## Root Cause

Go 的 `crypto/ssh` 库在认证时遵循服务器返回的允许方法列表。当密钥认证失败后，若服务器不返回 password 为允许方法，库不会主动尝试 password。
原先的 `authMethods()` 方法只是简单地将 Agent + KeyFile + Password 方法组成列表交给 `ssh.Dial`，缺少主动回退机制。

## Solution

在 `Connect()` 方法中实现两轮认证策略：
1. 首轮：使用全部可用方法（Agent + KeyFile + Password）
2. 若首轮失败且服务器同时配置了 KeyFile + Password：发起第二轮 Password-only 连接

在第二轮中，即使服务器返回不允许 password 方法，客户端仍主动发送 password 认证请求。
这样确保了在 key 认证失败的情况下，password 总能被尝试。

## Affected Files

- `asshc/infra/ssh/client.go` — `Connect()` 方法重构，提取 `setupKeepalive()` / `hasKeyAndPassword()` 辅助方法
